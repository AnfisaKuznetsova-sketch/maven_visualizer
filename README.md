# Визуализатор зависимостей Maven

Практическая работа №2 по конфигурационному управлению, вариант 15.
Этап 2: сбор данных о прямых зависимостях пакетов Java/Maven.

## 1. Общее описание

Программа принимает координаты пакета и URL Maven-репозитория,
самостоятельно загружает его POM-файл, разбирает XML и выводит прямые
зависимости в консоль. Менеджер Maven не запускается. Сторонние библиотеки
для получения зависимостей не используются; вся логика написана
на стандартной библиотеке Python.

Ветки проекта:

- `codex/stage-1` — первый этап: проверка и вывод конфигурации.
- `codex/stage-2` — второй этап: получение прямых зависимостей.

В отличие от первого этапа, теперь выводится результат анализа.
Шесть настроек больше не печатаются при каждом запуске.

Поддерживаются:

- POM с пространством имён Maven и без него.
- Прямые зависимости из `project/dependencies`, включая test и optional.
- Свойства `${name}`, вложенные свойства и `${project.version}`.
- Свойства, зависимости и управление версиями родительских POM.
- Версии из `dependencyManagement` и импортируемых BOM.
- Защита от циклов свойств, родителей и BOM; кеширование POM на время запуска.
- Понятные ошибки HTTP, соединения, XML, свойств и отсутствующей версии.
- Тестовый JSON-репозиторий для работы без интернета.

Секция `dependencyManagement` сама по себе не добавляет зависимости
в результат. Зависимости плагинов также не выводятся.
Родители и BOM могут загружаться для выяснения версий, но POM самих
прямых зависимостей не загружаются: транзитивный обход относится к этапу 3.

Ограничения реализации: не активируются Maven profiles, не используются
локальные настройки Maven или переменные среды из POM, не обрабатывается
relocation. Версии SNAPSHOT с временными метками и выбор версии из
диапазона по metadata пока не реализованы. Для демонстрации используются
фиксированные релизные версии. В вывод включены все объявленные scopes,
поэтому он может отличаться от списка библиотек runtime-classpath.

Граф, ASCII-дерево и SVG пока не создаются. Параметры `--output`,
`--ascii-tree` и `--filter` принимаются и проверяются для последующих этапов.
Фильтрация по подстроке начнёт применяться на этапе 3.

Структура проекта:

```text
src/
    config.py          Параметры и их проверка
    main.py            Точка входа и вывод результата
    maven.py           Загрузка POM, родители, BOM и зависимости
    pom.py             Разбор XML, свойств и полей зависимостей
    repository.py      Чтение тестового JSON-репозитория
tests/
    test_cli.py        Проверка параметров и запуска CLI
    test_maven.py      Проверка POM, наследования и ошибок загрузки
    test_repository.py Проверка тестового графа и точки входа
    fixtures/
        repository.json
scripts/
    demo.py            Демонстрация запуска и обработки ошибок
run.bat                Запуск в Windows
README.md              Документация
.gitignore             Исключение служебных файлов
```

## 2. Функции и настройки

| Опция | Назначение | По умолчанию |
| --- | --- | --- |
| `--package VALUE` | `groupId:artifactId:version` или имя тестового узла | Обязательная |
| `--repository VALUE` | HTTP(S)-адрес или путь к тестовому JSON | Обязательная |
| `--test-mode` | Использовать локальный JSON вместо сети | `False` |
| `--output PATH` | Путь будущего SVG-файла | `graph.svg` |
| `--ascii-tree` | Настройка ASCII-вывода для этапа 5 | `False` |
| `--filter TEXT` | Подстрока исключения для этапа 3 | Пустая строка |

Флаги указываются без значений: `--test-mode`, а не `--test-mode=true`.
Необязательный фильтр нужно опустить, если он не нужен.
Явно переданные пустые значения и пробелы по краям отклоняются.
Пути с пробелами заключаются в кавычки; относительные пути считаются
от рабочей папки терминала.

URL должен иметь схему HTTP(S) и имя сервера, без логина, пароля,
query-параметров и фрагмента. Путь `--output` проверяется на расширение
`.svg`, корректность имени и доступность папки для записи.
Проверка не создаёт и не изменяет файл изображения.

Функции `config.py`:

- `nonempty()` — проверка пустых значений и пробелов по краям.
- `build_parser()` — описание шести параметров и справки.
- `validate_package()` — проверка координат Maven или имени A–Z.
- `validate_url()` — проверка синтаксиса адреса репозитория.
- `validate_test_file()` — проверка наличия и доступности тестового файла.
- `validate_output()` — проверка пути будущего SVG-файла.
- `parse_cli()` — разбор и проверка всей конфигурации.

Функции и классы `maven.py`:

- `build_pom_url()` — формирование адреса POM по координатам.
- `load_pom()` — HTTP-загрузка с тайм-аутом 15 секунд.
- `PomModel` — свойства, управление версиями и объявления зависимостей.
- `MavenRepository.__init__()` — адрес репозитория, кеш и активные модели.
- `model()` — сбор модели, кеширование, контроль циклов и глубины.
- `parent_model()` — загрузка родительской модели.
- `management()` — объединение локальных, наследуемых и BOM-версий.
- `import_bom()` — импорт управляемых зависимостей BOM.
- `direct_dependencies()` — получение прямых зависимостей проекта.

Функции `pom.py`:

- `parse_pom()` — разбор XML и нормализация пространства имён.
- `element_text()` — чтение текста XML-элемента.
- `expand_properties()` — раскрытие свойств с контролем циклов.
- `project_properties()` — объединение свойств и алиасов координат.
- `dependency_fields()` — чтение полей объявления зависимости.
- `dependency_key()` — идентификация с учётом type и classifier.
- `resolve_dependency()` — применение управляемых версий и свойств.
- `dependency_coordinates()` — форматирование координат для вывода.

Функции `repository.py`: `validate_graph()` проверяет структуру JSON,
`test_dependencies()` возвращает прямых соседей указанного узла.

Функция `main()` в `main.py` выбирает режим и выводит результат.
В `scripts/demo.py` функция `scenarios()` задаёт примеры,
`run_case()` запускает один пример, `main()` выводит общий итог.

Коды завершения основной программы:

- `0` — успех или справка.
- `1` — ошибка загрузки, разбора POM или тестовых данных.
- `2` — ошибка параметров командной строки.

Ошибки основной программы выводятся в `stderr` без traceback.

## 3. Запуск и тестирование

Требуется Python 3.9 или новее. Сборка и установка зависимостей не нужны.
Команды выполняются из корня проекта `maven_visualizer`.

Справка:

```powershell
python src/main.py --help
```

Запуск с настоящим репозиторием (нужен интернет):

```powershell
.\run.bat --package junit:junit:4.13.2 --repository https://repo.maven.apache.org/maven2/
```

Запуск в PyCharm: **Run → Edit Configurations → Python**.
Укажите `src/main.py` в **Script path**, корень проекта
в **Working directory**, а в **Parameters** вставьте:

```text
--package junit:junit:4.13.2 --repository https://repo.maven.apache.org/maven2/
```

Нажмите **Apply → OK**, затем ▶. Запуск без обязательных аргументов
возвращает код `2` — это ожидаемая проверка конфигурации.

Автоматические тесты не требуют интернета:

```powershell
python -m unittest discover -s tests -v
```

Тесты проверяют параметры, XML, свойства, наследование и BOM,
отсутствие транзитивных загрузок, кеширование, ошибки HTTP/DNS/тайм-аута,
структуру JSON, прямые зависимости и вывод CLI.

Демонстрация (первый пример обращается к Maven Central):

```powershell
python scripts/demo.py
```

Демонстрация включает успешные и намеренно ошибочные команды.
Отметка `[OK]` означает совпадение фактического и ожидаемого кодов,
в том числе ожидаемый отказ для неправильных аргументов.
Итог успеха — `Итог: пройдено 9 из 9 проверок.`
Сам сценарий возвращает `0` при успехе и `1` при неожиданных результатах.

## 4. Примеры использования

Прямые зависимости JUnit:

```powershell
python src/main.py --package junit:junit:4.13.2 --repository https://repo.maven.apache.org/maven2/
```

Результат:

```text
Прямые зависимости junit:junit:4.13.2:
org.hamcrest:hamcrest-core:1.3
org.hamcrest:hamcrest-library:1.3
```

Другие примеры настоящих пакетов:

```powershell
python src/main.py --package org.slf4j:slf4j-simple:2.0.13 --repository https://repo.maven.apache.org/maven2/
python src/main.py --package com.google.code.gson:gson:2.11.0 --repository https://repo.maven.apache.org/maven2/
```

Тестовый репозиторий без интернета:

```powershell
python src/main.py --package A --repository tests/fixtures/repository.json --test-mode
```

```text
Прямые зависимости A:
B
C
```

Формат тестового файла — JSON-объект: имена узлов состоят из букв A–Z,
значения являются списками имён зависимостей. Каждый упомянутый узел
должен присутствовать в объекте. Пример: `{"A": ["B"], "B": []}`.

Пакет без прямых зависимостей:

```powershell
python src/main.py --package C --repository tests/fixtures/repository.json --test-mode
```

```text
Прямые зависимости C:
Прямых зависимостей нет.
```

Примеры ошибок:

```powershell
python src/main.py --package bad --repository https://example.org/
python src/main.py --package A --test-mode --repository missing.json
python src/main.py --package Z --test-mode --repository tests/fixtures/repository.json
```

Первые две команды завершаются с кодом `2`, последняя — с кодом `1`.
В PowerShell код можно проверить через `$LASTEXITCODE`.

Описание формата Maven:

- [Структура репозитория](https://maven.apache.org/repositories/layout.html).
- [Формат POM](https://maven.apache.org/pom.html).
- [Зависимости и BOM](https://maven.apache.org/guides/introduction/introduction-to-dependency-mechanism.html).
