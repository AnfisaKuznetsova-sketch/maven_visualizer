# Визуализатор зависимостей Maven

Практическая работа №2 по конфигурационному управлению, вариант 15.
Этап 3: граф зависимостей с учётом транзитивности, DFS и фильтрация.

## 1. Общее описание

Программа строит полный достижимый граф зависимостей пакета.
Источником служит настоящий Maven-репозиторий или тестовый JSON-файл.
Менеджер Maven не запускается, сторонние библиотеки получения
зависимостей не используются. Нужна только стандартная библиотека Python.

Версии работы сохранены в отдельных ветках:

- `codex/stage-1` — проверка и вывод конфигурации.
- `codex/stage-2` — получение прямых зависимостей Maven.
- `codex/stage-3` — транзитивный граф, фильтрация и циклы.

Реализованы требования этапа 3:

1. DFS без рекурсии: используется явный стек событий входа и выхода.
2. Исключение пакетов по пользовательской подстроке `--filter`.
3. Обработка циклов без бесконечного обхода с сохранением циклических рёбер.
4. Тестовый репозиторий с буквенными именами узлов и несколькими сценариями.
5. Результат этапа сохраняется отдельным коммитом.

Узел загружается один раз; повторная общая зависимость не считается циклом.
Для обнаружения цикла отдельно отслеживаются узлы текущего пути DFS.
Выводятся список смежности, порядок DFS и найденные циклические пути
по обратным рёбрам DFS. Это демонстрация обнаружения циклов,
а не перечисление всех возможных простых циклов графа.

Фильтр чувствителен к регистру. Подстрока ищется в полной строке
идентификатора узла: `groupId:artifactId:version` для Maven или буквенном
имени для JSON. Исключённый узел не включается в граф и не обходится.
Его потомок может попасть в результат, если доступен другим разрешённым
путём. Если исключён начальный пакет, выводится объяснение пустого графа.

JSON читается и проверяется один раз перед DFS. В граф попадают только
узлы, достижимые от начального пакета после применения фильтра.

Сохраняются возможности этапа 2: POM с пространствами имён, вложенные
свойства, родительские модели, dependencyManagement и BOM.
Родители и BOM читаются как метаданные; они не добавляются в граф
в качестве зависимостей сами по себе. Их разбор отделён от итеративного
обхода графа пакетов.

Ограничения: обходятся все объявленные scopes, включая test и optional.
Это граф объявленных зависимостей, а не выбранный Maven runtime-classpath.
Разные версии пакета являются разными узлами; конфликты версий не разрешаются.
Не активируются Maven profiles, не используются локальные настройки Maven,
не обрабатываются relocation, метаданные SNAPSHOT и выбор версий из диапазона.
Если POM не удалось загрузить или разобрать, программа сообщает об ошибке
вместо вывода частичного графа как полного.

SVG и ASCII-дерево появятся на этапе 5. Сейчас граф выводится списком
смежности; параметры `--output` и `--ascii-tree` сохраняются для этапа 5.

Структура проекта:

```text
src/
    config.py          Параметры и их проверка
    graph.py           Итеративный DFS, фильтрация, циклы и текстовый вывод
    main.py            Выбор источника, построение и вывод графа
    maven.py           Загрузка POM, родители, BOM и прямые зависимости
    pom.py             Разбор XML, свойств и полей зависимостей
    repository.py      JSON-репозиторий, загружаемый один раз
scripts/
    demo.py            Общая демонстрация параметров (нужен интернет)
    demo_graph.py      Восемь сценариев графов без интернета
tests/
    test_cli.py
    test_graph.py
    test_maven.py
    test_repository.py
    fixtures/
        repository.json
        chain.json
        diamond.json
        cycle.json
        self_cycle.json
        filter.json
        missing_node.json
run.bat
README.md
.gitignore
```

## 2. Функции и настройки

| Опция | Назначение | По умолчанию |
| --- | --- | --- |
| `--package VALUE` | `groupId:artifactId:version` или имя тестового узла | Обязательная |
| `--repository VALUE` | HTTP(S)-адрес или путь к тестовому JSON | Обязательная |
| `--test-mode` | Использовать локальный JSON вместо сети | `False` |
| `--output PATH` | Путь будущего SVG-файла | `graph.svg` |
| `--ascii-tree` | Настройка ASCII-вывода для этапа 5 | `False` |
| `--filter TEXT` | Подстрока исключения пакетов | Пустая строка |

Флаги указываются без значений: `--test-mode`, а не `--test-mode=true`.
Необязательный фильтр нужно опустить, если он не нужен.
Явно переданные пустые значения и пробелы по краям отклоняются.
Пути с пробелами заключаются в кавычки; относительные пути считаются
от рабочей папки терминала.

URL должен иметь схему HTTP(S) и имя сервера, без логина, пароля,
query-параметров и фрагмента. Путь `--output` проверяется на расширение
`.svg`, корректность имени и доступность папки для записи.
Проверка не создаёт и не изменяет файл изображения.

Функции `config.py`:

- `nonempty()` — проверка пустых значений и пробелов по краям.
- `build_parser()` — описание шести параметров и справки.
- `validate_package()` — проверка координат Maven или имени A–Z.
- `validate_url()` — проверка синтаксиса адреса репозитория.
- `validate_test_file()` — проверка наличия и доступности тестового файла.
- `validate_output()` — проверка пути будущего SVG-файла.
- `parse_cli()` — разбор и проверка всей конфигурации.

Функции и классы `maven.py`:

- `build_pom_url()` — формирование адреса POM по координатам.
- `load_pom()` — HTTP-загрузка с тайм-аутом 15 секунд.
- `PomModel` — свойства, управление версиями и объявления зависимостей.
- `MavenRepository.__init__()` — адрес репозитория, кеш и активные модели.
- `model()` — сбор модели, кеширование, контроль циклов и глубины.
- `parent_model()` — загрузка родительской модели.
- `management()` — объединение локальных, наследуемых и BOM-версий.
- `import_bom()` — импорт управляемых зависимостей BOM.
- `direct_dependencies()` — получение прямых зависимостей проекта.

Функции `pom.py`:

- `parse_pom()` — разбор XML и нормализация пространства имён.
- `element_text()` — чтение текста XML-элемента.
- `expand_properties()` — раскрытие свойств с контролем циклов.
- `project_properties()` — объединение свойств и алиасов координат.
- `dependency_fields()` — чтение полей объявления зависимости.
- `dependency_key()` — идентификация с учётом type и classifier.
- `resolve_dependency()` — применение управляемых версий и свойств.
- `dependency_coordinates()` — форматирование координат для вывода.

Функции и класс `repository.py`:

- `validate_graph()` проверяет структуру JSON.
- `read_graph()` читает и проверяет JSON-файл.
- `JsonRepository.__init__()` загружает репозиторий один раз.
- `JsonRepository.direct_dependencies()` возвращает прямых соседей.
- `test_dependencies()` сохраняет интерфейс запроса из второго этапа.

Функции и класс `graph.py`:

- `DependencyGraph` хранит список смежности и найденные циклические пути.
- `filtered_dependencies()` исключает имена и удаляет повторные рёбра.
- `build_graph()` выполняет итеративный DFS с явным стеком.
- `print_graph()` выводит рёбра, порядок обхода и циклы.

В `main.py` функция `make_repository()` выбирает источник данных,
`main()` строит граф и обрабатывает ошибки.
В `scripts/demo.py` функция `scenarios()` задаёт примеры,
`run_case()` запускает один пример, `main()` выводит общий итог.

В `scripts/demo_graph.py` функция `cases()` задаёт тестовые сценарии,
`run_case()` проверяет код завершения и содержание вывода,
`main()` суммирует результаты.

Коды завершения основной программы:

- `0` — успех, включая корректно обработанные циклы и исключение корня.
- `1` — ошибка загрузки, разбора POM или тестовых данных.
- `2` — ошибка параметров командной строки.

Ошибки основной программы выводятся в `stderr` без traceback.

## 3. Запуск и тестирование

Требуется Python 3.9 или новее. Сборка и установка зависимостей не нужны.
Команды выполняются из корня проекта `maven_visualizer`.

Справка:

```powershell
python src/main.py --help
```

Основная демонстрация третьего этапа без интернета:

```powershell
python scripts/demo_graph.py
```

Сценарий показывает цепь, общую зависимость, цикл, петлю, фильтрацию ветви,
исключение корня, пакет без зависимостей и ошибочный граф.
Для каждого сценария выводится `[OK]` или `[FAIL]`, в конце —
`Итог: пройдено 8 из 8 проверок.` Ошибка в последнем примере намеренная;
она должна дать код `1`. Сам демонстрационный скрипт возвращает `0`,
если все примеры отработали правильно.

Автоматические тесты без интернета:

```powershell
python -m unittest discover -s tests -v
```

Все 52 теста проверяют параметры, POM, свойства, наследование, BOM,
ошибки сети, JSON, транзитивный граф, DFS, фильтрацию и циклы.
Дополнительно проверяется цепочка длиннее лимита рекурсии Python.

Общая демонстрация параметров из прошлых этапов (нужен интернет):

```powershell
python scripts/demo.py
```

### Запуск в PyCharm

Запускаемый файл — `src/main.py`; рабочая папка — корень `maven_visualizer`.
В локальных настройках подготовлены конфигурации:

- `Maven - stage 3` — тестовый ромб и порядок DFS.
- `Maven - stage 3 cycle` — обнаружение цикла в JSON.
- `Maven - stage 3 filter` — исключение ветви по подстроке.
- `Maven - stage 3 real` — граф настоящего JUnit (нужен интернет).
- `Maven - graph demo` — все восемь демонстрационных сценариев.
- `Maven - all tests` — все автоматические тесты.

Настройки `.idea` локальные и не включаются в Git. При клонировании
создайте конфигурацию **Python** через **Run → Edit Configurations**:
укажите `src/main.py` в **Script path**, корень проекта
в **Working directory**, а в **Parameters** вставьте:

```text
--package A --repository tests/fixtures/diamond.json --test-mode
```

Нажмите **Apply → OK**, затем ▶. Запуск без обязательных параметров
возвращает код `2` — это ожидаемая проверка конфигурации.

## 4. Примеры использования

### Транзитивность и общая зависимость

```powershell
python src/main.py --package A --repository tests/fixtures/diamond.json --test-mode
```

```text
Граф зависимостей A:
A -> B, C
B -> D
D -> (нет зависимостей)
C -> D
Порядок DFS: A -> B -> D -> C
Циклов нет.
```

Узел `D` достигается через `B` и `C`, но обрабатывается один раз.
Изолированный узел `Z` из этого файла в результат не попадает.

### Цикл

```powershell
python src/main.py --package A --repository tests/fixtures/cycle.json --test-mode
```

```text
Граф зависимостей A:
A -> B
B -> C
C -> A
Порядок DFS: A -> B -> C
Обнаружены циклы:
A -> B -> C -> A
```

### Фильтрация

```powershell
python src/main.py --package A --repository tests/fixtures/filter.json --test-mode --filter BLOCK
```

```text
Граф зависимостей A:
A -> KEEP
KEEP -> LEAF
LEAF -> (нет зависимостей)
Порядок DFS: A -> KEEP -> LEAF
Циклов нет.
```

Узлы `BLOCK` и достижимый только через него `HIDDEN` исключены из анализа.

### Настоящий репозиторий Maven

```powershell
python src/main.py --package junit:junit:4.13.2 --repository https://repo.maven.apache.org/maven2/
```

Начальный пакет связан с `org.hamcrest:hamcrest-core:1.3` и
`org.hamcrest:hamcrest-library:1.3`. В графе также показывается связь
`hamcrest-library` с `hamcrest-core` и порядок DFS.

Формат тестового файла — JSON-объект: имена узлов состоят из букв A–Z,
значения являются списками имён зависимостей. Каждый упомянутый узел
должен присутствовать в объекте. Пример: `{"A": ["B"], "B": []}`.
Пустые списки и циклические связи допустимы.

Ошибочный тестовый граф:

```powershell
python src/main.py --package A --repository tests/fixtures/missing_node.json --test-mode
```

Результат — сообщение `Ошибка: Неизвестная зависимость A: B` и код `1`.
В PowerShell код можно посмотреть через `$LASTEXITCODE`.

Описание формата Maven:

- [Структура репозитория](https://maven.apache.org/repositories/layout.html).
- [Формат POM](https://maven.apache.org/pom.html).
- [Зависимости и BOM](https://maven.apache.org/guides/introduction/introduction-to-dependency-mechanism.html).
