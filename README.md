# Визуализатор зависимостей Maven

Практическая работа №2, вариант 15. Этап 1: минимальный CLI-прототип
с конфигурацией. Язык реализации — Python.

## 1. Общее описание

Программа принимает параметры командной строки, проверяет их и выводит
все шесть настроек в формате `ключ=значение`.

На первом этапе программа не получает зависимости, не обращается к сети,
не строит граф и не создаёт SVG-файл. Опции фильтрации и ASCII-дерева
сохраняются в конфигурации для следующих этапов.
Готовые менеджеры пакетов и библиотеки получения зависимостей не используются.
Внешние Python-библиотеки не требуются.

Структура проекта:

```text
src/
    config.py       Разбор и проверка параметров
    main.py         Точка входа и вывод конфигурации
tests/
    test_cli.py     Автоматические проверки
    fixtures/
        repository.json  Пример тестового репозитория
scripts/
    demo.py         Демонстрация успешных запусков и ошибок
run.bat             Запуск в Windows
```

## 2. Функции и настройки

| Опция | Назначение | Значение по умолчанию |
| --- | --- | --- |
| `--package VALUE` | Анализируемый пакет | Обязательная |
| `--repository VALUE` | URL или путь к тестовому файлу | Обязательная |
| `--test-mode` | Использовать тестовый репозиторий | `False` |
| `--output PATH` | Имя будущего SVG-файла | `graph.svg` |
| `--ascii-tree` | Включить вывод ASCII-дерева | `False` |
| `--filter TEXT` | Подстрока для исключения пакетов | Пустая строка |

`--package` в обычном режиме принимает координаты
`groupId:artifactId:version`, например `org.example:demo:1.0`.
Проверяется формат, существование пакета на этом этапе не проверяется.
В тестовом режиме имя состоит из заглавных латинских букв: `A`, `B`, `ABC`.

`--repository` в обычном режиме должен быть HTTP(S)-адресом с именем
сервера, без логина, пароля, query-параметров и фрагмента.
Проверяются также синтаксис и диапазон порта. Доступность сервера
на этом этапе не проверяется.
В тестовом режиме требуется существующий файл, доступный для чтения.
Его содержимое на первом этапе не разбирается.

`--output` должен оканчиваться на `.svg`. Папка должна существовать
и быть доступна для записи. Проверяются недопустимые символы и
зарезервированные имена файлов Windows. Если файл уже существует,
проверяются его тип и доступность записи; содержимое не изменяется.
Проверка прав предварительная: создание файла на будущих этапах
потребует отдельной обработки ошибок записи.

Флаги `--test-mode` и `--ascii-tree` указываются без значений.
Отсутствие флага означает `False`, наличие — `True`.
Например, `--ascii-tree=false` — ошибка.

`--filter` исключает пакеты, имя которых содержит заданную подстроку.
На первом этапе выводится только само значение настройки.
Если фильтрация не нужна, опцию следует опустить. Явно переданное
пустое значение или значение с пробелами по краям считается ошибкой.

Пути с пробелами нужно заключать в кавычки.
Относительные пути отсчитываются от текущей папки терминала.

Функции `src/config.py`:

- `nonempty(value)` — проверяет пустые значения и пробелы по краям.
- `build_parser()` — описывает параметры, справку и значения по умолчанию.
- `validate_package(value, test_mode)` — проверяет формат имени пакета.
- `validate_url(value)` — проверяет адрес репозитория без сетевого запроса.
- `validate_test_file(value)` — проверяет наличие файла и доступ к чтению.
- `validate_output(value)` — проверяет путь будущего изображения.
- `parse_cli(argv=None)` — разбирает аргументы и запускает проверки.

`src/main.py`: функция `main()` выводит проверенную конфигурацию.

`scripts/demo.py`:

- `scenarios()` задаёт примеры и ожидаемые коды завершения.
- `run_case(title, args, expected)` запускает пример и сравнивает коды.
- `main()` запускает все примеры и выводит общий итог.

Ошибки выводятся в `stderr`, параметры при ошибке не выводятся.
Код завершения: `0` — успешный запуск или справка, `2` — ошибка параметров.
При ошибках параметров Python traceback не выводится.

## 3. Запуск и тестирование

Требуется Python 3.9 или новее. Сборка и установка зависимостей не нужны.
Следующие команды выполняются из корня проекта.

Справка:

```powershell
python src/main.py --help
```

Запуск в Windows через PowerShell:

```powershell
.\run.bat --package org.example:demo:1.0 --repository https://repo.maven.apache.org/maven2/
```

Автоматические тесты стандартной библиотекой `unittest` (9 тестов):

```powershell
python -m unittest discover -s tests -v
```

Демонстрация двух успешных запусков и ошибок всех шести параметров:

```powershell
python scripts/demo.py
```

Демонстрация печатает каждую команду, ожидаемый результат и вывод программы.
Для каждого примера появляется отметка `[OK]` или `[FAIL]`.
Итог успешного выполнения: `Итог: пройдено 9 из 9 проверок.`
Сообщения об ошибках в отрицательных примерах ожидаемы: они показывают,
что неверные параметры обработаны правильно.
Демонстрация завершается с кодом `0`, если все проверки пройдены,
и с кодом `1`, если найден неожиданный результат.

### Запуск в PyCharm

Откройте папку `maven_visualizer` через **File → Open**.
Выберите установленный интерпретатор Python 3.9 или новее.

В **Run → Edit Configurations** создайте конфигурацию **Python**:

- **Script path** — `src/main.py` внутри проекта.
- **Working directory** — корневая папка `maven_visualizer`.
- **Parameters** — строка ниже:

```text
--package A --repository tests/fixtures/repository.json --test-mode --output graph.svg --ascii-tree --filter B
```

Нажмите **Apply → OK** и запустите конфигурацию кнопкой ▶.
В панели **Run** появятся шесть строк параметров и код завершения `0`.
Запуск `main.py` без обязательных аргументов вернёт ошибку с кодом `2`.

Для демонстрации можно отдельно запустить `scripts/demo.py` без аргументов.
Файл `tests/test_cli.py` также запускается без аргументов для проверки тестов.
Настройки `.idea` локальные и не включаются в репозиторий.

## 4. Примеры использования

Обычный режим с настройками по умолчанию:

```powershell
python src/main.py --package org.example:demo:1.0 --repository https://repo.maven.apache.org/maven2/
```

Результат:

```text
package=org.example:demo:1.0
repository=https://repo.maven.apache.org/maven2/
test_mode=False
output=graph.svg
ascii_tree=False
filter=
```

Тестовый режим со всеми опциями:

```powershell
python src/main.py --package A --repository tests/fixtures/repository.json --test-mode --output demo.svg --ascii-tree --filter B
```

Результат:

```text
package=A
repository=tests/fixtures/repository.json
test_mode=True
output=demo.svg
ascii_tree=True
filter=B
```

Ошибки каждого параметра можно воспроизвести отдельно:

```powershell
python src/main.py --package bad --repository https://example.org/
python src/main.py --package a:b:1 --repository wrong-url
python src/main.py --package A --repository tests/fixtures/repository.json --test-mode=false
python src/main.py --package a:b:1 --repository https://example.org/ --output graph.png
python src/main.py --package a:b:1 --repository https://example.org/ --ascii-tree=1
python src/main.py --package a:b:1 --repository https://example.org/ --filter=
```

Дополнительный пример отсутствующего тестового файла:

```powershell
python src/main.py --package A --test-mode --repository missing.json
```

Каждая ошибочная команда выводит справочную строку использования,
описание ошибки и возвращает код `2`. В PowerShell код последней
команды можно посмотреть через `$LASTEXITCODE`.
